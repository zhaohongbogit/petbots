# 小七局域网文字助手（开发版）

手机负责文字输入和显示；i.MX7 负责本地计划、明确设备指令及可选的本地模型。运行时不需要互联网、代理或云端账号，不录音、不播报。

这是独立的两个应用，不覆盖原有小七、电话扬声器或录音日记应用：

| 端 | 应用 ID | 功能 |
|---|---|---|
| i.MX7 | `com.zhb.offlineassistant` | 前台局域网服务、任务队列、计划、表情、音量控制、本地模型进程 |
| 小米 | `com.zhb.offlinechat` | 纯文字聊天、任务进度、断线后查询、取消、私有本地历史 |

手机只申请 INTERNET；板端另申请前台服务、媒体音量权限。两端均未申请麦克风权限。开发版允许 ADB run-as 进行私有配对配置，尚未按正式发行包加固。

## 已实现的指令

- `你好`、`你是谁`、`谢谢`：明确的本机固定短答；这不等于通用模型聊天。
- `帮助`：查看实际接入的能力。
- `查询设备状态`：查看模式、存储、媒体音量和模型文件状态。
- `计划：写报告30分钟，复盘20分钟；开始19:00；可用120分钟`：复用现有 HomeworkPlanner，生成25分钟专注/5分钟休息的文字时间表；不创建日历、提醒或外部任务。
- `请展示开心表情`：复用现有 ExpressionAction 和面孔页面；返回“已启动动作”，不把动画全部结束当作已验证。
- `音量调到80`：明确设置媒体音量百分比，不触发播放。

其他短消息才进入可选本地模型。模型输出仅显示为文字，不会传给指令分发器。首版没有把任意自然语言都当作可执行设备任务。

## 构建

依赖 Android SDK29 / Build Tools35.0.0、JDK、NDK28.2.13676358、CMake3.22.1，以及仓库已有的 `demo/android-voice-weather/third_party/llama.cpp`。不改动旧小七源码，但编译时复用其 Java 类。

```sh
bash native/build.sh
bash test.sh
bash build.sh
```

输出 `build/board.apk` 和 `build/phone.apk`。本地测试签名和模型均忽略，不提交私有配对文件。

## 安装与配对

在本目录执行（Python3.11+）：

```sh
python3 provision.py
python3 check_connection.py
```

脚本只针对已确认的 NXP `000000c4cddac462` 和小米 `9c79ecb0` 安装独立测试包；每次重新配置只停止这两个新包。小米可能要求解锁并允许USB安装。`--board-only` 可单独准备板端。

Android Things旧版 adbd 的 exec-in 可能静默丢弃输入；本脚本使用 shell -T、有长度上限的输入与写后核对。`--skip-install` 可对已经安装的两端重新配置而不触发系统安装提示。

初次生成256位随机配对凭据，仅经 ADB 管道写入两端私有目录，不在主机保存、不打印。重复配置复用板端现有凭据。更换设备应先明确目标再修改脚本。

板端仅监听 wlan0 的 IPv4 地址、端口8777。手机设置页只修改内网IP。两端须处于互通的局域网；Wi-Fi断开或板端地址变化后可停止/重新启动板端服务，再修改手机地址。

HTTP采用配对鉴权，**局域网传输未加密**。适合自己的热点或可信局域网，不应将端口映射到公网；公共Wi-Fi隔离也可能导致无法互通。该版本未提供TLS或蓝牙链路。

## 模型边界

引擎使用ARMv7静态 llama.cpp、上下文256tokens、短回复最多64tokens、约150秒计算超时；仅在完整短句或模型结束标记出现时提交答案。超时/失败不会把片段伪装成完整回复，不切换云端。应用层等待最多190秒。

Qwen3-0.6B 的 pure Q2_K 版本真机测试约150秒未完成，片段不可读，已排除该版本。混合Q2_K配置在调整进程地址空间上限后也于约152秒超时，片段不可读。因此本轮未部署模型，通用模型聊天尚未达到可用标准，不能视为具备原有云端聊天质量或速度。缺少模型时，固定短答、计划和明确设备命令仍可使用；通用聊天明确报告未准备。

可选模型路径为应用私有 `files/models/Qwen3-0.6B-Q2_K.gguf`；这是调试用接口，只有后续模型验证通过且检查设备剩余空间后才应使用 `provision.py --model /absolute/path/Qwen3-0.6B-Q2_K.gguf`。模型文件存在仅说明已准备文件，不证明回复质量通过。

## 协议与恢复

- `GET /health`：只读健康信息。
- `POST /input`：JSON `{id, text}`，单任务串行，id必须唯一；相同id/原文幂等返回已有状态，冲突原文拒绝。
- `GET /status?id=...`：查询结果；手机断线/回到前台只查询，不自动重发。
- `POST /cancel`：JSON `{id}`；停止未完成处理，不撤销已执行动作。

所有端点需要 `X-Pet-Key`，请求体限4KiB/500字，禁止分块请求体。最多保存64条任务和24条板端上下文消息；手机最多100条消息。应用私有历史持久化；服务重启把未完成任务标为中断，不自动执行。手机可以明确取消任务或仅结束手机查询，后者不会停止设备处理。

`check_connection.py` 只检查健康、未知任务404和无凭据403，不提交任何聊天或设备操作。完整手机发送流程、表情和音量真机验证需在目标和测试文本明确后进行；构建和解析单元检查不能代替该验证。
