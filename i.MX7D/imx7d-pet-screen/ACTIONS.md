# 表情动作执行

本轮取代旧的 `reply + expression` 协议，采用 `reply + actions`，无需安装 Agents SDK。

## 输入和执行

- `ExpressionAction.resolve` 只匹配完整、明确的短命令，直接执行并给出本地回应。不会因普通句子包含“生气”就执行动作。复杂说法仍走模型。
- 模型返回 `{"reply":"...","actions":[{"type":"set_expression","name":"angry","intensity":0.95,"duration_ms":12000}]}`。
- 所有动作在执行前整体校验：七种名称、有限数值强度 0–1、整数时长 1000–30000ms，最多五个；不合法则整条失败，不执行部分动作。
- 空 actions 保留当前表情及原有到期时间；新动作替换旧队列。序列依次执行，最后恢复平静。
- 思考中是临时显示层，覆盖情绪但不改变底层动作。请求失败不覆盖已有情绪。
- 页面后台暂停回调，恢复时继续处理到期动作；销毁清理回调。不会在后台持续绘制。
- 强度目前直接影响生气时的眉形、眼睑和嘴形；其他表情保留各自造型，尚未逐个实现强度插值。
- 日志记录请求 ID、决策来源、动作序号、名称、强度和 applied/expired；不记录输入全文、回复或密钥。

## 回归命令

- 你表现出来很生气 → angry / 0.95，本地执行。
- 再生气一点 → 根据当前强度增加 0.25，上限 1。
- 不要生气，笑一个 → happy。
- 先哭，再笑 → sad 4 秒，happy 8 秒。
- 恢复平静 / 停止表演 → neutral，并替换现有序列。
- 我今天很生气 / 假设、引用、否定等不匹配直接执行规则，交给模型理解。

`tests/ExpressionActionTest.java` 可用 javac/java 运行，覆盖完整命令、强度、否定、自述、引用和非法参数。

调试支持通过 Intent 的 draft 参数填入文字，必须手动点击发送；不会自动执行。现场截图和动作日志在 build/action-verification 下。语音、长时间运行和所有自然语言组合不在本轮保证范围。

## 本轮验证

- 28 项 JVM 断言通过；Android 构建、签名校验及 iMX7 覆盖安装通过。
- 真机明确指令：强烈生气、进一步提高强度、否定生气转微笑均匹配预期；序列日志显示 sad → happy → neutral，且有同一请求 ID。
- 复杂说法经真实代理返回 angry / 0.95 并执行。
- 发现模型会将用户情绪自述误判成表演，新增完整情绪自述模式保护和本轮指令提示。匹配保护时，即使模型返回动作也不执行；显式要求展示表情的句子不走此保护。
- 最终回归：复杂表演请求返回 angry / 0.95；“我今天很生气，你能陪我聊聊吗？”触发 self_report 保护，最终动作数量为 0，原表情按原定时到期恢复。
- 代理实测不接受本轮尝试的后置系统消息（HTTP 400），最终版本将约束合并在首条系统消息中，真实请求已恢复成功。错误日志现在记录受限的 HTTP 状态或协议错误码，便于定位。
