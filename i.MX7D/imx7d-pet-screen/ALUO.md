# i.MX7D 阿洛：表情与语音

当前板端入口使用 **Silero VAD + 同一份 Paraformer Small int8（短句唤醒、指令和确认）+ 系统中文离线 TTS**，替换此前持续运行的 Vosk 听写。手机版不变。主界面只有表情和底部文字，没有文字输入、调试按钮、语音/唤醒/天气开关。

## 使用

1. 应用前台、麦克风权限允许后自动准备本地模型并持续监听。首次加载约需数十秒，以实际“正在聆听”状态为准。
2. 说“你好阿洛”，等待耳机回应“收到”，再说完整指令，例如“上海明天天气怎么样”。当前采用分步对话，唤醒与命令请分开说。
3. VAD 判断讲话结束后，停止采集并整句识别，原始文字显示在表情底部。此方案不在唤醒前持续听写，也不提供逐字 partial，不做识别别名替换。
4. 天气先回读城市和日期，播报结束、确认麦克风就绪后有 8 秒窗口。明确回答“是的”才查询；拒绝、含糊、超时不查询，同城市日期有 30 秒冷却。
5. 播报暂停录音，结束后隔离 500ms，再自动监听；暂不支持打断。离开前台停止采集，后台结果不会触发业务或回复。

中文离线声音、唤醒和真实天气默认开启，不自动调整音量。优先使用 USB 耳麦输入。语音和原始录音不上传；自然语言结构化分类仍可复用应用已有的语义服务配置，明确天气句式在本地解析，天气请求使用原有 WeatherClient。没有新增服务账号或配置界面。通用自由聊天能力未在本次新增。

## 皇包车旅行服务

现已在同一应用接入 hbc-agent 测试订单服务，纯语音进入、多轮收集、报价和单次创建订单审批。使用与部署见 [HBC.md](HBC.md)。旅行转写文字会发送给所配置的Agent服务，音频不上传；测试登录及实际订单业务验收见独立报告。

## 代码与构建

`ChatActivity` 保留表情与底部两行文字；`VoiceController` 保留唤醒、命令、确认、天气及播报状态机。`WakeUtterance` 对完整短句做唤醒判定，保留原始转写；`SherpaSpeech` 管理 44.1kHz 双声道采集、应用内到16kHz的重采样、有界队列、模型校验和本地切句；`SherpaNative` / `native/sherpa_engine.c` 提供 JNI。`BoardSpeech` 留作历史 Vosk 对照，已经不是产品输入实现。

模型版本、校验、下载、原生工具与构建说明见 [native/README.md](native/README.md)。从项目根目录执行：

```sh
python3 i.MX7D/imx7d-pet-screen/native/fetch_models.py
bash i.MX7D/imx7d-pet-screen/build.sh
bash i.MX7D/imx7d-pet-screen/build.sh --reuse-model
bash i.MX7D/imx7d-pet-screen/tests/device/build.sh
```

完整包包含约 79MiB 模型；更新包约 18MiB，要求应用专属 `speech-models` 目录已有同一套模型，冷启动校验三个文件的大小和 SHA-256。两个包均为 API27/ARMv7，不含本地 Qwen。当前板子空间有限，使用更新包，不清除应用数据，不修改系统存储阈值。签名材料仅在忽略的 build 目录保留。

## 验证边界

[2026-10-30 对比与真人验证记录](reports/2026-10-30-sherpa/README.md) 记录当前结果；[前一轮 H340 / Vosk 诊断](reports/2026-10-29-human-audio/README.md) 为历史依据。

`SherpaReplayTest` 使用实际 JNI 和本地真人录音，检查唤醒、正确天气与普通听写以及近音负样本，不打开麦克风、TTS 或外部业务。它不能代替真人唤醒、用户听见回复和完整对话验证。历史 AluoIntegrationTest 的 Vosk 原生用例需要旧 APK 和旧模型，不能用于新引擎验收。

原始录音只保存在本机临时目录与设备诊断目录，不入库、不上传。长期唤醒误报/漏报、不同说话人、远场与噪声环境仍需持续验证。
