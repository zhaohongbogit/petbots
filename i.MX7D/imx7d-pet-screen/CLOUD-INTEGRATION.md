# 云端语音接入准备

状态更新（2026-09-09）：文字对话已接入个人服务器 OpenAI 兼容代理；设备端已完成短录音、ASR multipart 客户端、本地中文 TTS 和说话嘴型。当前代理调用 `/audio/transcriptions`、`/audio/speech` 均不可用，因此尚未完成云端识别闭环。

## 前置验收

- 录音计时与音频实际时长接近，连续人声完整。
- 耳机可回放，声音速度、音量正常。
- 动画与录放音资源采样完成。
- 确认语音识别、对话、语音合成供应商及服务端运行位置。

## 接入结构

设备按键录音 → 自有代理 `/audio/transcriptions` → 识别文字 → 现有 `/chat/completions` → Android 本地 TTS → 耳机播放。

供应商密钥仅存服务端环境中；Android 客户端的 `speech_key` 只能是自有代理访问凭证，不能配置供应商原始密钥。
首次使用按键触发，采用完整短音频请求，暂不实现远场唤醒和全双工。
客户端上传 16 kHz、16-bit、单声道 WAV；代理负责供应商鉴权和请求转发。
客户端应处理超时、取消、网络中断与可理解的错误提示。

## 设备端配置

- `speech_base`：自有代理的 OpenAI 兼容 `/v1` 基地址。
- `speech_model`：默认 `FunAudioLLM/SenseVoiceSmall`。
- `speech_key`：自有代理访问凭证，只保存在应用私有配置中。

只有三个字段齐全时主界面录音按钮才会开始采集；否则显示“语音识别服务尚未配置”，不会产生上传。

## 2026-09-09 编排验证

在开发机启动假 ASR 上游和修改后的自有代理，i.MX7D 可通过局域网访问代理健康检查。设备录制 7,000 ms 后上传 224,351 字节 multipart，代理原样转发二进制并返回测试转写；转写随后进入真实对话模型，执行 happy/0.9 表情并启动本地 TTS。测试后已清除设备上的局域网地址和测试凭证。

这一结果覆盖设备到代理的协议和整条编排，不覆盖硅基流动真实识别质量。远端代理部署并配置真实上游后，还需用实际人声核验识别文本、耗时和失败重试。

## 部署后的设备配置

远端代理更新并通过健康检查后，在开发机执行：

```bash
python3 i.MX7D/imx7d-pet-screen/provision_chat.py --with-speech
```

脚本复用现有自建代理地址和代理访问凭证，只写入应用私有配置，不显示凭证，也不会把供应商原始密钥写入设备。需要关闭语音识别时执行 `--clear-speech`，不会影响文字对话配置。

## 2026-09-09 远端部署结果

- 修改后的代理已部署到 `101.200.126.74`，`hbc-llm-proxy` 容器重建后为 healthy。
