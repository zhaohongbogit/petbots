# H340 真人收音、识别与回复排查（2026-10-29）

**结论：完整真人闭环未通过。H340原始人声采集和实际耳机TTS播放已分别得到人工确认；当前Vosk真人识别/唤醒不合格，真人流程没有进入命令、口头确认或真实天气请求。**

## 设备与测试边界

目标是 i.MX7D `000000c4cddac462`、Android Things/API27，宠物应用 `com.zhb.petscreen`。本轮实际设备为 Logitech USB Headset H340，Android输入id43/type22，ALSA card2；硬件输入44.1kHz双声道。当前生产AudioRecord请求16kHz单声道，由系统转换。与10月28日的SGTL5000/3.5mm模拟输入不是同一路径。

用户确认使用H340并配合发声。没有刷机、改系统库、改播放音量或麦克风增益；没有上传音频、使用云端ASR或发送真实天气请求。

## 实际发现与修改

1. 原版日志有多次64帧队列积压后停止重启；不是“AudioRecord读到了数据就代表识别正常”。
2. 原来每句重新创建关键词识别器并复放整句，增加了实时路径开销。现在缓存并预热关键词解码器；按原始词时间跳过前置静音，只复核讲话开头最多2秒，仍保留原始转写与独立唤醒证据。
3. 临时结果最多约每250ms读取一次。补充慢帧/唤醒耗时、最终转写和TTS开始/完成日志。
4. 优化后观察到约1～1.9秒的句末复核，也仍有持续慢帧和队列溢出；**没有宣称积压已根治**。本轮同一真人录音的离线通用识别也失败，不能只靠缓存或增大队列承诺完整闭环。
5. 新增同签名诊断instrumentation：MicrophoneProbeTest（原始采音）、HumanReplayTest（精确录音复放）、RestrictedHumanReplayTest（受限词表对照）、ReplyProbeTest（实际离线TTS）。无产品配置开关或文字输入入口。
6. 尝试只读USB采集控制，打开 `/dev/snd/controlC2` 被设备权限拒绝；没有提升设备权限、没有写控制值，也没有确认当前麦克风硬件增益。

主界面仍保持表情与底部转写，唤醒、播报、天气默认启用，正常返回产品时自动监听；保留工作区其他未提交改动。

## 下一步

当前证据足以确认H340收音与回复通路可用，但不支持宣称当前Vosk具备可用的真人唤醒和天气识别能力。需要对真人语料评估更适合ARMv7的唤醒/识别模型，或另行确认是否允许局域网机器承接识别；后者会改变音频的数据流向，尚未实施。3.5mm模拟链路、长时稳定性、多说话人/口音/远场、真实天气接口仍未验收。
