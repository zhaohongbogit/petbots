# 小七：iMX7 文字陪伴宠物

## 当前功能

- 800×480 原生界面：左侧宠物表情，右侧对话和输入框。
- 设备输入框、三个中文快捷话题、小米手机中文输入三种入口。
- 请求中显示思考状态，可取消；失败保留原文，避免重复自动发送。
- 最近 12 轮对话保存在设备应用私有设置中，供上下文和重新打开恢复；“新对话”会先确认再清空。
- 默认入口为 ChatActivity；原音频、蓝牙和屏幕测试从“设备测试”进入。

## 模型代理

按用户指定配置直连个人服务器的 OpenAI 兼容代理：

- Base URL：`http://101.200.126.74/llm-proxy/v1`
- 模型：`Qwen/Qwen3.6-35B-A3B`
- 请求：`POST /chat/completions`，JSON messages，`stream=false`，`enable_thinking=false`，`max_tokens=384`。
- 参考 hbc-agent 的 `src/model/llm-runtime.ts`（Chat Completions）和 `src/agent/order-agent.ts`（关闭思考输出），未修改 hbc-agent。
- Key 由 `provision_chat.py` 从 hbc-agent 本地 `.env` 读取，只配置到 Android 应用私有设置。脚本、源码及 APK 不包含密钥字面值；不记录请求文本、回复正文或认证头。
- 当前使用用户指定 HTTP 地址，属于当前开发配置；聊天文本经个人代理发送给模型服务。
- “记忆”仅指最近 12 轮上下文，不是长期用户画像或知识库。

## 构建部署

```sh
bash i.MX7D/imx7d-pet-screen/build.sh
bash i.MX7D/imx7d-phone-speaker/build.sh
adb -s 000000c4cddac462 install -r i.MX7D/imx7d-pet-screen/build/pet-screen.apk
adb -s 9c79ecb0 install -r i.MX7D/imx7d-phone-speaker/build/phone-speaker.apk
python3 i.MX7D/imx7d-pet-screen/provision_chat.py
```

第一次使用手机输入，先运行 `i.MX7D/imx7d-phone-speaker/provision_lan.py` 配置两台设备的局域网地址与独立配对凭据，再运行 `provision_chat.py` 回到宠物对话页。手机打开“iMX7 手机音箱”→“给小七发文字”。手机仅向 iMX7 提交文字，不持有代理密钥。

手机文本输入使用 iMX7 前台临时监听的 8766 端口，源 IP 和配对凭据双重检查；`POST /input` 使用 JSON，单次最多 500 字，返回任务 id；`GET /status?id=...` 查询回答。重复同一 id 不会再发起模型请求。离开 iMX7 对话页关闭接收服务。

## 验证记录

- 已完成构建、签名检查、两台设备覆盖安装和页面截图检查。
- 代理鉴权 `/models` 返回 HTTP 200，目标模型存在。
- 小米手机发送中文 → iMX7 → 个人代理 → 模型 → 两端显示，第一轮实际请求约 2463 ms。
- 第一条验证输入为虚构玩具名“小橘”，模型按要求回复“记住了。”；第二轮询问名称，模型正确回答“小橘”，上下文验证通过。
- 三次实际请求耗时约 2463 / 697 / 1460 ms，手机接收回复成功；仅为本次样本，不是延迟承诺。
- 覆盖安装并重新启动后，三轮对话恢复成功。
- 已扫描 APK 内容，未发现配置中的代理密钥。
- 设备自带输入法为 LatinIME，尚不提供 iMX7 本机拼音输入；建议中文使用手机输入页。

未验证：长期运行、弱网完整矩阵、12 轮截断边界、模型内容质量系统评测。该版本不调用语音识别、语音合成或播放接口。

最终部署补充：修正全屏布局导致键盘遮挡的问题，实机截图确认键盘弹出时输入框与发送按钮仍可见。基于系统合成开销，将待机表情设为静态，仅思考时以约 2 Hz 更新。最终版本安装后保留并继续使用原有会话，用户手机实际连续对话已观察到。验证截图与定向日志在 build/chat-verification/；未做长期性能基准。

## 2026-09-08：宠物面孔作为默认主页

- 默认显示全屏 Canvas 卡通脸：额头纹、眉毛、眼睛、鼻子、脸颊和嘴巴；不显示聊天记录、输入框或状态文字。
- 右下角 `•••` 打开文字调试面板；“返回面孔”或面板中的系统返回操作收起面板。软键盘展开时保留输入和发送按钮。
- 面孔低频眨眼，轻触会短暂眯眼微笑；模型请求期间显示思考表情，请求失败显示失落表情。没有模拟已接入语音的聆听或说话状态。
- 面板仍在同一 Activity 内，开关面板不停止文字接收服务、不清空历史、不取消模型请求；设备测试入口保留在面板中。
- 构建、APK 签名校验、iMX7 安装、默认面孔、面板打开与键盘布局已验证；截图位于 `build/face-verification/`。语音闭环、长期运行性能和所有模型状态的真机表情回归尚未验证。

## 对话驱动的情绪表情

- 支持平静、喜悦微笑、生气、悲伤流泪、开怀大笑、忧愁担心、惊讶七种表情，通过眉形、眼形、视线、嘴形、眼泪和额头符号区分。
- 可发送“笑一个”“请表现生气”“做一个悲伤的表情”“开怀大笑一下”“露出忧愁的表情”“惊讶一下”“恢复平静”。模型回复采用 `reply` 与 `expression` 的 JSON 对象；只把 `reply` 展示和保存为对话内容。手机文字入口共用这条处理路径。
- 设备严格校验七种表情名称和非空回复，不执行模型返回的任意指令。格式错误显示请求失败，不将 JSON 原文展示给用户。
- 请求过程中为思考表情，成功后立即显示模型选择的表情，保持到下次回复或手动切换。轻触微笑短暂覆盖后恢复。新对话恢复平静。请求失败显示担心表情。
- 调试面板中的“表情”可离线预览，并填入对应测试文字；预览不调用模型，重新打开面板点“发送”才能验证真实对话。
- 对明确展示表情的要求优先执行；用户描述自己的心情时由模型结合上下文共情。复杂否定和多种表情连续演出的准确性没有保证，当前每条回复仅选择一个表情。

本次验证记录：构建和签名校验通过，已覆盖安装到 iMX7。通过屏幕调试入口提交真实模型请求，平静、喜、怒、哀、乐、愁、惊讶七种均返回对应的合法表情并完成绘制；逐项真机截图保存在 `build/face-verification/`。语音输入、长时间性能以及复杂自然语言边界未在本次验证。
