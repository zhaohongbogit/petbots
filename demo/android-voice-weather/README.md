# 阿洛（Android，0.9.0）

当前音频同时进入两个共享 Vosk 模型的识别器：**无约束原始转写**用于实时显示和句末记录，**独立受限词表识别器**判断开头是否说了“阿洛”。命令经过 **声学唤醒入口 → 回应“收到” → Qwen3-0.6B 异步判断意图 → 回读城市并询问 → 明确同意后查询与播报**。Qwen 不阻塞转写。不加载 Qwen3-ASR，不按天气关键词判断任务，不使用拼音纠错、城市别名替换或 N-best 重排。历史版本结果保留在 docs，不能视为当前结果。

## 唤醒与接收命令

- 待机时说“阿洛，上海明天天气怎么样”。声音入口使用独立的 `阿 洛` 受限词表，保留 `[unk]` 接收其他语音；只接受片段开头完整的两个唤醒音节、合理时长及每词置信度不低于 0.85 的结果。没有把所有语音强制解释为唤醒词；置信度是受限词表下的解码指标，不是实际准确率。原始转写即使显示“那 咯”或“落 上海…”，也不会被改写；声学检测命中另记一条日志。句中提及“阿洛”不作为开头唤醒。唤醒只代表向设备发话，是否支持该任务仍由 Qwen 判断。
- 也可单独说“阿洛”：有效任务出队后回应“收到”，播报结束并经过 0.5 秒回声隔离后开启 8 秒窗口，只接收下一句非空完整句。该句接收后也回应“收到”，再运行 Qwen；窗口过期需重新唤醒。此窗口不提供跨句语义记忆，不保证理解“明天呢”等省略了目标的表达。
- 不带唤醒称呼、且不在上述窗口或当前确认阶段的完整句，只保留原始转写与麦克风 WAV，不进入 Qwen、不回应。临时文字、播报重叠片段、旧任务、助手关闭时的片段均不触发回应。
- 普通命令通过队列并实际出队后，只回应一次“收到”。回应完成后才提交 Qwen，避免快速模型结果打断回应；失效、过期或在出队前被挤掉的任务不回应。Qwen 尚未加载完成时任务可以等待，仍受 15 秒有效期限制。停止、重置、切换助手或离开前台会取消待完成的回应交接，迟到回调不能启动旧任务。
- 唤醒后的任务经 Qwen 判断为非天气任务、城市无法匹配，或要求今天/明天以外的日期时，回应“我还不会”，不进入天气确认或查询。播报期间及结束后的 0.5 秒仍隔离回声；缺少离线 TTS 时显示同样的文字。天气确认窗口内的无关回答仍继续等待“是的／不用”。
- 天气询问后的 8 秒确认窗口仍可直接回答“是的／不用”，无需再次唤醒、不重复回应“收到”；也支持“阿洛，不用”。确认任务仍交给 Qwen 判断，收到不等于执行成功。
- 原始转写保留 Vosk 实际输出；声学命中后，依据两个识别器的同源绝对词时间，仅向 Qwen 提交唤醒音节之后的原始词。没有把错字替换成“阿洛”，也不使用“那咯／安诺”等转写别名触发。文字模拟仍要求文本开头为“阿洛”，支持词间空白与首尾标点。声音检测明确拒绝时，不再退回文本前缀触发。确认窗口仍可直接回答，播报重叠保护优先于声学命中。缺少中文离线 TTS 时仅显示“收到”，之后继续识别；播报失败也保留文字反馈，无法承诺一定听到声音。
- 界面分别显示 Vosk 原始转写和独立声学唤醒结果；例如原文是“二楼”时，不据此直接认定唤醒成功或失败。播报隔离结束时切分流式识别段，播报期的回声段仍不可触发确认，之后新开始的回答按确认窗口判定。“需要”等片段即使被 Qwen 判为同意或拒绝，也只按不明确回答记录；执行天气查询仍需完整明确的肯定回答与模型判断一致。

## 准备与安装

需要 Python 3.11+、JDK 17/21、Android SDK 35、NDK 28.2.13676358、CMake 3.22.1。APK 只支持 arm64-v8a，最低 API 26。

```bash
python3 tools/prepare_model.py
python3 tools/prepare_qwen.py
./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest lintDebug
android run --device=<serial> --apks=app/build/outputs/apk/debug/app-debug.apk --activity=cn.aihongbo.voiceweather.MainActivity
python3 tools/deploy_qwen.py --device <serial> --adb <adb-path>
```

Vosk small-cn-0.22 下载包约 42MB，准备脚本固定 SHA-256，生成的模型随 APK 打包，首次启动复制到应用私有目录。Qwen3-0.6B Q4_K_M 约 378 MiB，单独部署并校验长度及 SHA-256。模型缺失时展示失败原因，不使用规则回退。模型、原生依赖和生成文件不进入 Git；只构建文本推理库可使用 `prepare_qwen.py --source-only`。当前不需要 `prepare_qwen_asr.py` 或 sherpa-onnx AAR；历史 Qwen3-ASR 设备文件可保留，但不加载。

## 测试与性能显示

1. Vosk 与 Qwen 独立加载；Vosk 就绪即可开始转写，Qwen 加载失败时也能继续记录。界面显示两边加载时间与进程 PSS，不能将它们当作单模型内存。
2. 单条郑州、快速郑州、郑州压力、上海合成音频不含唤醒称呼：先点击“阿洛”，等待回应完成，8 秒内点击样本按钮；未唤醒时样本只记录转写。样本走相同流式解析与界面回调，按采样时钟模拟逐帧输入，文件结束时冲刷最终结果。每 80ms 送入音频帧，Vosk 临时结果变化即更新“实时转写（临时）”；临时文字可能回改，不写入正式日志，也不提交 Qwen。Vosk 检测停顿给出最终结果后，才更新“最近完整句”和“连续转写记录”，随后经过唤醒入口。界面分别显示 Vosk 耗时和 PSS、Qwen 排队时间/推理耗时/PSS、两边队列长度与 Qwen 忙时完成的转写条数。语义结果附带对应输入，避免和最新转写混淆。PSS 是整个进程的快照，不是单个模型大小或峰值。
3. Qwen 根据整句语境判断意图、城市和日期；当前不能可靠恢复同音城市错字，准确率限制见报告。代码不对城市词作替换，界面保留 Vosk 原文；命令入口只做唤醒和格式处理。未提城市才允许使用默认城市，不明确时应返回 ambiguous。模型仍可能猜错，必须在询问中回读目标城市，经用户确认后再执行。
4. 询问播报完成后 8 秒内回答“是的／不是的／不用”。确认回答使用独立 Qwen 分类任务；确认窗口内的无关回答只记录，继续等待明确回答。
5. 默认真实天气关闭，使用明确标记的模拟数据。只有开启真实天气并明确同意后才访问 Open-Meteo。
6. “Vosk + Qwen 样本自检”运行 8 条合成 PCM，写入 `files/vosk-qwen-self-test.json`，直接测试模型，不经过唤醒、不播报、不查询。文字入口测试唤醒和语义流程，不能作为语音识别证据。
7. 点击“开始麦克风监听”现场试说；离开前台或重置即停止录音，丢弃旧推理结果。关闭天气助手只转写，不调用语义模型，但仍保留已加载的模型。

麦克风为 16kHz 单声道、PCM16，每帧 1280 个采样（80ms）。采集线程持续读取并调用专属 Vosk 识别器，不再等待能量分段后整体解码；它与 Qwen 执行器独立。AudioRecord 设置约 2 秒设备缓冲，用于吸收短暂解码抖动；算力不足仍可能发生音频丢失，不宣称无限负载下无丢字。

句末由 Vosk 原生端点判断，模型尾部静音阈值约 0.5～2 秒，不能把 80ms 输入帧当作首次出字或句末延迟保证。最长连续语段保护为 20 秒，超过后冲刷该段原生最终结果并继续下一段；它不保证切在语法句号处。停止/重置会取消旧上下文，未成句尾部若已冲刷出来则只记录，不执行助手行为。

临时结果仅用于当前显示，会被后续临时结果覆盖；完整文字交给独立 IO 线程记录到 `files/transcripts.jsonl`，约 2MB 轮换，不上传转写。当前页面保留最近约 12000 字正式记录。

麦克风音频按 Vosk 句末或 20 秒保护边界保存到应用私有目录 `files/recordings/<会话时间-UUID>-<句子序号>.wav`，格式为 16kHz、单声道、16bit 小端 PCM WAV。每句包含最多 0.5 秒前置缓冲及检测句末所需的尾部静音；停止、重置、离开前台时也保存已经开始的尾句，但不触发尾句助手行为。纯静音不会单独建文件；能量或识别文字触发开始的片段即使最终文字为空也保存，播报重叠片段也保存，因此可能包含噪声及扬声器回声。合成样本自检不保存录音。

采样线程只缓冲当前句，完整段交给独立单线程写入器，等待队列最多 4 段；队列满时跳过该段保存并记录错误，不阻塞识别。先写 `.part` 文件，关闭后原子改名为 `.wav`，随后在该工作线程调用 `SentenceWavRecorder.UploadHook.onFileReady(File)`。当前明确接入 `NO_UPLOAD` 空实现，不发起网络请求，也没有持久化上传队列或重试。正常停止会提交尾句；进程突然终止时内存中的音频和待写任务可能丢失，可能遗留 `.part` 文件。录音约 1.92MB/分钟，当前不自动清理，需关注长期占用。应用卸载或清除数据会删除这些文件。


## 代码与行为边界

- `VoskAsr.java`：每个连续音频源有独立的原始转写和声学唤醒识别器，共享只读模型；提供 partial/result/final 与单独的声学证据。原始转写不加词表限制，词时间只用于切分 Qwen 输入；两个识别器的词时间都跨 `reset()` 延续，不能重复叠加片段偏移。活动音频流结束后才释放模型，不跨线程销毁解码器。有限的旧批量接口仅保留给显式独占自检与历史测试。
- `StreamingTranscriber.java`：临时结果去重、Vosk 句末事件、累计解码耗时与音频时间、20 秒长段保护；音频能量只帮助标记说话时间，不筛掉低音量文字，不作内容匹配。
- `PcmMicrophone.java`：80ms 连续 PCM 采样并在专属线程流式解码，不判断说话内容；Qwen 忙和播报标记不暂停采样。与播报重叠的整段音频标为只记录，避免把助手回声当作同意；这是时段隔离，不是声学回声消除，期间真人插话也只记录。
- `SentenceWavRecorder.java`：前置音频缓冲、按句后台写入 WAV、停止尾句收尾及上传预留回调；当前无实际上传。
- `WakeEvidence.java`：独立声学结果的置信度、时长、位置检查，以及按词时间提取命令；不改写原始转写。
- `WakeCommandGate.java`：声学唤醒或文字模拟的开头称呼、单独唤醒后的一句接收窗口、确认阶段豁免；不判断具体业务意图。
- `CommandHandoff.java`：普通命令等待“收到”回应结束后才交给 Qwen，取消与重复回调保护；确认任务直接交接。
- `IntentBacklog.java`：语义队列总容量 8 条，确认优先、同类保持接收顺序；满时优先跳过最早普通任务，保留全部已经完成的转写。普通任务接收后超过 15 秒、确认超过 30 秒跳过语义，避免积压后突然插话。
- `MainActivity.java`：麦克风流式解码、诊断样本、Qwen、文字日志 IO、天气网络各自线程/执行器。Qwen 使用 2 个原生计算线程，略降低线程优先级，给转写留出 CPU 余量；仍共享硬件资源，软件分离不等于物理资源完全隔离。
- `QwenSemanticInterpreter.java`：Qwen 输出 intent/city/date；确认阶段单独输出 yes/no/other。JSON grammar 只约束输出形状，不匹配输入内容。
- `DialogueEngine.java`：只接收结构化模型结果，管理确认、超时与同城市同日期 30 秒冷却。窗口内收到的回答可等待推理完成；模型延迟不算用户迟答。
- `CityCatalog.java`：314 城市精确有效性校验和坐标查询，不参与近音替换。日期仅支持今天/明天，不支持的日期拒绝执行，后天不强制换成明天。
- `OfflineQwen.java` / `app/src/main/cpp`：Q4_K_M CPU 推理，15 秒原生截止及取消。ASR 重置后丢弃旧结果，后台结束后释放，不强制中断原生解码。
- 对话任务绑定录音会话和对话阶段，重置或进入下一阶段时清理旧语义任务；旧“是的”不能作为新询问的同意。确认窗口按收到音频/文字的时间判断，窗口内回答可等待 ASR/Qwen 完成。只有当前阶段有效的语义结果才能执行天气流程。缺少离线 TTS 时只显示文字。

```bash
adb -s <serial> install -r -t app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s <serial> shell am instrument -w cn.aihongbo.voiceweather.test/androidx.test.runner.AndroidJUnitRunner
```

默认仪器测试使用模拟天气。显式加 `-e live true` 才执行真实天气请求。不要使用结束后卸载应用的 connected 测试方式。状态机单元测试、真实模型处理合成音频、界面/TTS 回调、真人麦克风与树莓派性能是不同验证层级。当前验证见 [0.9.0 报告](docs/流式双链路验证-0.9.0.md)。

“阿洛”入口初次失败及文字流程见 [初次真机记录](docs/2026-10-23-aluo-device/README.md)。后续独立声学唤醒修复见 [声音唤醒修复报告](docs/2026-10-23-aluo-fix/README.md)：原始转写保留，53 项单元测试、原生正负样本、PCM 页面流程、回声保护及外部扬声器到真实麦克风的模拟天气流程分别通过；另有同机回采丢词的失败，不能声称所有真人或声学场景通过。办公区不修改电脑和手机音量，测试脚本已移除自动音量控制，后续不自动外放。
