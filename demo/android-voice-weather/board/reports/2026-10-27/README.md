# i.MX7D ARMv7 Vosk 实测

日期：2026-10-27，Asia/Shanghai。

结论：ARMv7 Vosk/JNA 可在该开发板加载并完成中文识别。单识别器短句预热后通常能跟上输入，但存在冷启动和运行抖动，尚不能承诺连续实时；当前双识别器配置在两种输入下均持续慢于输入，不宜直接用于常开实时监听。内存暂时能容纳本验证进程，主要瓶颈表现为 CPU/延迟；这不代表完整应用有足够资源。

## 设备与版本

- iot_imx7d_pico，i.MX7 Dual，双核 Cortex-A7，最高 1.2GHz。
- Android Things 1.0.15，Android 8.1/API 27，armeabi-v7a，系统可见内存 500436 KiB。
- 独立包名 `cn.aihongbo.voiceweather.board`，minSdk 27、targetSdk 35。
- Vosk 0.3.75、JNA 5.18.1，复用现有 small-cn-0.22 assets。
- `:app` 手机目录、构建配置及原生实现未修改；仅 settings.gradle 增加 `:board`。
- 没有 Qwen 模型/推理库，没有网络或录音权限，没有真实天气请求。

## 方法

四次独立 instrumentation 进程依次运行：single 默认、dual 默认、single 无附加静音、dual 无附加静音。每次加载一个模型，创建一个或两个识别器；单进程内连续运行不限速 3 轮、按音频时钟供帧 3 轮，共 24 轮。

同一条合成 PCM 为 2.09025 秒“郑州明天的天气怎么样”；默认追加 3 秒静音，无附加静音组在文件结尾强制取得 final。所有 24 轮文本均为 `郑州 明天 的 天气 怎么样`。这是单一固定样本识别结果，不是泛化准确率或唤醒准确率。

RTF = 解码及结果读取总耗时 / 输入音频时长，低于 1 表示本轮平均处理速度快于输入。首次不限速轮单列；其余不限速轮视为预热后结果。所有平均 RTF 都不能代替最坏帧耗时、长时间积压或真实音频丢失指标。

200ms 采样整个测试进程 PSS、RSS、原生堆、Java 已用堆；后两组另记录 VmSwap。PSS 是采样最大值，不能当作精确峰值、纯模型内存或与 RSS 同时刻的数值。仪器测试和采样本身有开销，组间系统状态不同，不能把两组内存差直接当作唤醒识别器的独占内存。

## 结果

| 配置 | 模型加载 | 采样最大 PSS | 采样最大 RSS | 首轮 RTF | 预热后不限速 RTF | 按时供帧 RTF | 按时供帧最大完成滞后 |
|---|---:|---:|---:|---:|---|---|---|
| 单识别器 + 3秒静音 | 7.602秒 | 140.37 MiB | 141.41 MiB | 3.016 | 0.775 / 0.739 | 0.690 / 0.690 / 0.682 | 328 / 311 / 304ms |
| 双识别器 + 3秒静音 | 5.928秒 | 148.39 MiB | 159.87 MiB | 3.344 | 1.211 / 1.144 | 1.163 / 1.136 / 1.151 | 924 / 760 / 858ms |
| 单识别器，无附加静音 | 6.373秒 | 136.37 MiB | 147.07 MiB | 5.686 | 0.747 / 0.735 | 1.081 / 0.716 / 0.699 | 826 / 291 / 271ms |
| 双识别器，无附加静音 | 5.802秒 | 143.50 MiB | 153.64 MiB | 6.324 | 1.221 / 1.169 | 1.154 / 1.214 / 1.209 | 502 / 623 / 610ms |

每组首次解码都出现约 5 秒的单帧阻塞。单识别器默认组预热后每轮有 20 帧超过 80ms，双识别器为 28 帧；不能把“平均 RTF < 1”解释为每帧均能在 80ms 内完成。无附加静音组只保留 2.09秒短句，结束时强制冲刷，不能用于比较自然句末延迟。

单识别器可以继续验证“预热后开始录音、单解码器持续转写”的路线。当前生产双解码器配置应先调整唤醒策略或解码负载，再考虑真实麦克风常开；本次没有为了提高数字而改写原始转写或删除手机版唤醒保护。

## 实际完成的验证

- 构建：`:board:assembleDebug`、`:board:assembleDebugAndroidTest` 通过。
- 静态检查：`:board:lintDebug` 通过，0 错误、7 警告；涉及 SDK/依赖新版本提示、ARMv7 专用包缺少 ChromeOS ABI、备份声明和图标。没有屏蔽 Lint 错误。
- APK 检查：仅 `lib/armeabi-v7a/libvosk.so`、`libjnidispatch.so`，没有 `libvoice_qwen.so` 或 GGUF 模型。共用 assets 中仍保留原许可证文字。
- 签名：开发调试 APK 的 v2 签名校验通过。
- 开发板：应用和测试 APK 安装成功；四次仪器测试分别 `OK (1 test)`，约 54.803 / 57.331 / 32.711 / 36.384 秒。测试通过表示成功运行及产生非空识别，不表示实时性能达标。
- 启动：`am start -W` 返回 `Status: ok`，Activity 为独立 board MainActivity。未做屏幕截图或交互视觉检查。
- 差异检查：新增内容限定在 board 模块及 settings.gradle 的模块注册，保留其他未提交改动。

初始安装尝试出现一次 APK manifest 解析失败；等待构建完成后用 `--no-streaming` 安装成功。未进行系统修改、重启、清除数据或卸载旧应用。

## 尚未验证

真实麦克风输入路由、AudioRecord 丢帧、长时间连续输入、多样说话人/城市/噪声、声学唤醒正负样本、回声、TTS、WAV 写盘与 UI 并发、后台/开机常驻、远端语义、真实天气接口均未验证。现有约 2 秒录音缓冲能否应对首次解码的约 5 秒阻塞，也未实测；真实录音前需要处理预热和就绪状态。

## 原始证据

- `benchmark-single.json`、`benchmark-dual.json`：默认 3秒尾静音，初版测试 APK；SHA-256 见 `initial-artifacts.json`。
- `benchmark-single-dense.json`、`benchmark-dual-dense.json`：无附加静音，增加 silence_ms 参数和 VmSwap 记录后的测试 APK；SHA-256 见 `final-artifacts.json`。解码主体未改变。
- `device.txt`：选择性设备信息，采样时的剩余内存不是测试全程峰值。
- APK 位置（相对本文件目录）：`../../build/outputs/apk/debug/board-debug.apk`，测试 APK 为 `../../build/outputs/apk/androidTest/debug/board-debug-androidTest.apk`。
