# 随身语音日记（NXP i.MX7D）

独立 Android 应用 `cn.aihongbo.diary`，版本 0.1.0，面向已连接的 Android 8.1 / ARMv7 NXP 开发板。不替换阿洛或手机版，不刷机。

## 使用

1. 先点击“开始录音”，说一句话，然后点击“停止录音”和对应分段的“回听”，确认有清晰人声。请让谈话参与者知悉录音。
2. 确认音质后开始当天录音。前台服务和 CPU 唤醒锁维持后台录音；通知内可停止；最长24小时。重启、断电或进程被强行终止后不会自行恢复录音。
3. 停止后点击“离线转写待处理录音”，保持应用在前台。单 Vosk 中文自由听写，无天气词表限制；完成分段逐一保存，重复操作跳过已完成分段。单个损坏分段显示失败并允许重试，继续处理后续分段。
4. 时间线按文件开始时间排序，逐字稿附句子起止时间。点击“导出逐字稿 TXT”选择保存位置；没有系统文件选择器时可用 adb 导出。

本版本先录音、后转写，不提供边录边出字、说话人识别、自动摘要或待办提取。

## 录音与数据

- MediaRecorder：AAC-LC / M4A，16kHz，单声道，32kbps。约14.4MB/小时、346MB/24小时（十进制估算，含容器后有偏差）。
- 默认每约1.2MB切换分段，使用 API 26 的 `setNextOutputFile` 交接，不主动 stop/start 重启麦克风。以字节数分段，时长约5分钟，依编码器而变。
- 启动要求剩余150MiB，录音中每2秒检查，低于100MiB停止保留已有文件。不自动删除旧录音。需定期导出清理；目前没有应用内删除功能。
- 应用私有 `files/diary/`：`<毫秒时间>.m4a` 为声音；`.m4a.start` 为分段开始回调的墙钟时间；`.m4a.txt` 为完成逐字稿；`.txt.part` 为未完成输出；`.m4a.error` 为失败信息；`events.txt` 为开始、分段、停止事件。
- 句子时间由分段开始的墙钟时间加 Vosk 单词偏移估计，不是校准过的采样级时间。系统时间修改会影响跨分段排序。
- 原录音和离线模型仅存在本机；没有 INTERNET 权限或上传接口；关闭系统备份。TXT 只包含文字，不包含原录音。
- AAC 文件须正常停止/完成分段才能封装完整。断电或崩溃可能损坏最后一段，已完成分段不依赖最后一段才能转写。
- 无人声或识别不出时明确标注“未识别到文字”，不生成假逐字稿；转写仍可能有错漏，应保留原音核对。

## 构建与安装

在 `demo/android-voice-weather` 执行：

```sh
./gradlew :diary:assembleDebug :diary:assembleDebugAndroidTest :diary:lintDebug
adb -s 000000c4cddac462 install -r -g diary/build/outputs/apk/debug/diary-debug.apk
adb -s 000000c4cddac462 shell am start -n cn.aihongbo.diary/.MainActivity
```

复用本地 `app/src/main/assets/model-cn` 和现有 Vosk/JNA 依赖；模型未纳入 Git，需要在本地准备原项目使用的中文模型。模型授权见原 assets/licenses。

## 真机测试注意

`DiaryDeviceTest#captureRolloverDecodeAndTranscribe` 会真实打开麦克风约15秒，必须先获得现场录音授权，不可作为无提示的日常自动测试。服务非导出；测试分段阈值仅由应用内部 Intent 的 `segment_bytes` 调小，范围16KB–1.2MB，正常界面固定默认值。

`knownAacSpeechProducesText` 使用既有合成清晰样本转成 AAC（`src/androidTest/assets/known-speech.m4a`），不采集麦克风，不把合成录音写入日记时间线。测试资产只进入测试 APK。
