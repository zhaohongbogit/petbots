# Vosk 与 Qwen 链路验证（0.7.0）

日期：2026-10-22。设备：已连接的 Xiaomi/POCO 23049RAD8C，Android 15，arm64；安装版本 versionCode 7 / versionName 0.7.0。

## 完成的改动

- `app/build.gradle`：恢复 Vosk Android 0.3.75 与 JNA 5.18.1，移除 sherpa-onnx 与 Kotlin 运行时依赖，升级版本。APK 约 59.5 MiB，解包确认包含 Vosk 模型、libvosk 和文本推理库，不含 sherpa/ONNX 原生库。
- `VoskAsr.java` 替代活跃的 `QwenAsr.java`：复制内置中文小模型到私有目录，复用识别器、每句重置状态。无语法约束、热词、N-best 重排、拼音候选、城市别名替换。
- `QwenSemanticInterpreter.java`：整句输入 Qwen3 判断 intent/city/date，确认阶段独立判断 yes/no/other。仅移除 ASCII 词间空格进行格式归一，界面和日志保留 Vosk 原文；没有转写正则或城市改字。城市有效性、日期支持范围继续验证模型输出。
- `MainActivity.java`：更换 ASR 加载和样本入口，展示两类模型各自加载时间、加载后内存、转写/语义/流水线时间，以及处理前、转写后、语义后的进程 PSS。普通聊天、确认、冷却、TTS 与天气流程保留。
- `PcmMicrophone.java`：同步引擎说明和线程名称，仍使用原来的能量分段；没有新增内容匹配。
- `tools/prepare_model.py`：恢复固定下载 SHA-256 的 Vosk 模型准备脚本；生成资源忽略入 Git。README 同步当前链路、准备步骤、测试和限制。
- 设备测试改为 `VoskQwenDeviceTest`、`VoskQwenUiTest`，并扩充 `QwenSemanticDeviceTest`。准确率测量与安全拒绝分开记录，未把无法恢复城市算成识别正确。

## 耗时与内存

冷启动 UI 显示：总模型加载 1521ms，Vosk 649ms，Qwen 846ms；Qwen 加载后 PSS 522 MiB，双模型就绪 PSS 651 MiB。随后 dumpsys 的 PSS 约 640 MiB、RSS 约 761 MiB，数值会随采样时机变化。

以下来自独立音频测试，耗时不包括录音、0.7 秒端点等待、模型加载、TTS 或网络查询；复用识别器后冷热样本存在差异：

内存比 0.6.0 已记录的约 2 GiB UI 快照明显下降。但 Vosk 首条与困难样本仍可能比 Qwen3-ASR 更慢，不能声称所有语音都提速；当前多数等待仍在 Qwen 语义阶段。不同版本测试不构成严格控制条件的性能基准。

## 郑州误识别结论

- 标准和快速合成郑州音频本身转写正确，随后城市、日期和意图都正确。
- 压力音频丢失了城市和天气词，最终只得到“你 能 查 一下 中 明天 的 坚强”。Qwen 返回 other；没有拿默认城市继续询问或执行。这是未恢复，不计为识别成功。
- 独立文字能力测试：“正中明天天气怎么样”“郑重明天的天气怎么样”均未恢复郑州（0/2），返回 other；执行拦截通过。这两条是固定误听文字测试，不冒充真实音频识别证据。
- 非查询陈述“郑重提醒大家明天天气有变化”和“把东西放在正中间”未触发天气询问。
- 通用提示词对比发现，增加纠错描述或对话示例会使小模型把正确郑州句误判或丢掉城市。最终采用基本语义较稳定的提示词，未引入任何错误词到城市的硬编码映射。
- 后天输入未执行；测试仅验证不支持日期被拒绝，没有把拒绝执行算成日期原词提取正确。

因此，当前已完成 Vosk → Qwen 的链路替换，但“仅靠 Qwen3-0.6B 稳定恢复郑州同音错字”尚未解决。

## 未验证与限制

没有真人麦克风识别、口音/噪声、电机声、持续运行或断网实验；本轮天气流程使用模拟数据，未新增真实天气请求。TTS 验证为系统回调与界面流程，不代表进行了人工听音评审。

这版仍在讲话停顿后整段解码，并非边录音边显示的流式 Vosk UI；推理和播报期间丢弃新音频。Android 内存结果不能证明树莓派 3B 的 1GB 整机内存足够，也不能外推 CPU 速度。

旧的 Qwen3-ASR 文件未从手机存储中删除，但当前 APK 没有相应依赖，也不加载它们。
