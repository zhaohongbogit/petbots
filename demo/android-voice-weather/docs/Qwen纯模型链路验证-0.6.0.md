# 纯 Qwen 语音链路验证（0.6.0）

## 需求与改动

用户要求只用 Qwen3 识别语音，不使用正则匹配。原来的 Qwen3-0.6B 是纯文本模型，不能接收声音，因此接入专用 **Qwen3-ASR-0.6B**，文本 Qwen3-0.6B 只承担天气语义与确认分类。

- `QwenAsr.java` 通过 sherpa-onnx 1.13.8 Android CPU 运行官方 Qwen3-ASR 的 INT8 ONNX 转换版；没有配置热词、FST 或同音替换。
- 删除当前应用的 `CityResolver`、`SpeechCityInterpreter`、`CityCorrectionPolicy`、`PhoneticCityCandidates` 和 `LlmCityCorrector`。上一版源码/测试的本机备份在忽略目录 `build/qa/pre-qwen-asr-source.zip`；历史报告仍保留。
- `QwenSemanticInterpreter` 对整句运行模型，不先按关键词筛选。正常阶段提取 intent/city/date；确认阶段只输出 yes/no/other，不能直接查询或生成天气。
- `DialogueEngine` 只接收结构化模型结果，没有文本正则或关键词判断。保留确认窗口、状态限制及城市/实际日期冷却。
- 保留城市表的精确有效性校验；模型输出的日期原词只验证是否为受支持值。它们不扫描原始转写，不按近音改字，也不替模型推断意图。
- `MainActivity` 分别展示原始转写、模型 JSON、ASR 与语义耗时，增加只转写开关和纯 Qwen 音频自检。
- `PcmMicrophone` 只做录音和能量分段，停顿约 0.7 秒提交，最长 10 秒；不识别任何词语，不保存录音。
- `prepare_qwen_asr.py` 固定 AAR 和模型归档的 SHA-256，解压后保存逐文件清单；手机逐文件校验，最后发布 manifest。应用启动时再次校验。
- 移出旧 Vosk 模型资源，移除 Vosk/JNA 依赖；检查最终 APK 不含旧库或模型。模型缺失/失败时没有其他 ASR 或规则回退。

## 模型与来源

- 原始语音模型：[Qwen/Qwen3-ASR-0.6B](https://huggingface.co/Qwen/Qwen3-ASR-0.6B)，Apache-2.0。
- 部署转换版：[sherpa-onnx Qwen3-ASR](https://k2-fsa.github.io/sherpa/onnx/qwen3-asr/index.html)，INT8 `2026-03-25` 归档。
- Android AAR 1.13.8，归档/组件校验值见 `qwen-asr-manifest-0.6.0.json`。
- 文本模型保持 Qwen3-0.6B Q4_K_M，官方 Q8_0 本地重量化，来源见 `qwen-model-manifest-0.5.0.json`。这是独立文本模型，不冒充音频识别器。
- 语音模型组件总大小约 987 MB；文本模型另占 396.7 MB（十进制）。模型不打包进 APK，不进入 Git。

## 开发中发现并修复的问题

1. 初版同时让小模型输出意图、城市和 day 整数，出现“后天→明天”和“不用→yes”的错误。首轮原始输出保留在 `qwen-semantic-initial-0.6.0.json`。不以“有结构化 JSON”当作理解正确。
2. 改成单独的确认分类任务，日期按原词输出后验证支持范围，不用正则修正输入。增加“没有城市时 null、日期不是城市”的模型指令。
3. 最终模型仍可能将不支持日期的天气请求分类为 other；报告保留这一标签误差。执行层要求该日期不查询，测试不把安全拒绝等同于完整语义标签准确。
4. 首次资源排除配置未实际排除 Vosk 模型。通过解包检查发现后，将旧生成资源移出 `assets` 并重建，随后再次检查 APK。

## 真机验证

当前手机 `23049RAD8C`，Android 15，arm64-v8a；覆盖安装版本 code 6 / name 0.6.0，保留应用数据。

- `QwenAsrDeviceTest` 实际读取 8 条 16kHz 合成 PCM，经 Qwen3-ASR 转写，再运行 Qwen3 语义。报告含未修改的文字、两个阶段耗时、音频时长与进程 PSS。
- `QwenSemanticDeviceTest` 用 10 条固定转写测试语义与执行约束。它不是声音识别测试。unsupported 日期要求不执行，标签误差仍保留在 JSON。
- `QwenOnlyUiTest` 用实际模型验证普通聊天不插话、后天不查询、郑州音频回读、否定不查询、上海音频与肯定音频后天气查询、重置丢弃旧结果。
- 完整 instrumentation **OK (3 tests)，131.705 秒**，见 `instrumentation-0.6.0.txt`。11 项单元测试 0 失败。真机界面流程实际完成一次上海真实天气查询，并收到系统离线 TTS 的完成回调；没有人工听音或真人麦克风验证。

### 固定文本与执行约束

10 条固定转写报告见 `qwen-semantic-0.6.0.json`：3 条支持天气请求正确提取城市/日期（含未提城市 null）、普通聊天与郑重提醒为 other、否定请求不执行、是的/不是的/不用分类正确。后天天气被模型标为 other 而非 weather，属于语义标签误差，但保留 date=后天，执行层拒绝查询。

因此不能将“执行约束测试通过”表述为全部语义字段 100% 正确；10 条 intent 标签为 9/10 匹配。对于 no/other，模型还可能输出字符串 `"null"`；这些字段不用于查询目标，未偷偷转成默认城市。后天天气的控制检查只要求不执行，原始标签误差保留在报告中。

UI 流程文字快照见 `qwen-only-ui-report-0.6.0.txt`：普通聊天未回读、后天未查询、郑州音频回读后“不是的”拒绝、上海音频与肯定音频后真实查询、重置后旧任务未继续交互。

## 边界与尚未验证

- 合成文件直接解码不经过麦克风、扬声器或现场噪声；没有用用户真实发音、方言、多说话人或电机噪声验证。
- 不保证所有语义输出正确，尤其是含糊回答、复杂日期、多城市及提示注入；模型没有规则回退。没有将样本命中率外推为通用识别准确率。
- 文本推理支持 15 秒原生截止/取消；ASR 目前只能在重置后丢弃旧结果，不能强制中途终止。没有注入长期超时、模型被杀或低内存故障。
- 推理与播报期间暂停接收新采样，避免无界积压；没有证明持续监听完全无遗漏，也未测长期功耗、温升或续航。
- 天气仍联网查询；模型推理在本机 CPU 执行。本轮没有关闭整机网络进行断网回归。
- 没有树莓派 3B 实测，尤其不能用手机构建/运行结果替代其 1GB 内存可行性验证。
