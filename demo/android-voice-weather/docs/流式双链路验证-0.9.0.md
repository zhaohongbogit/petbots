# Vosk 流式双链路验证（0.9.0）

日期：2026-10-22。设备：Xiaomi/POCO 23049RAD8C，Android 15，arm64。已更新 versionCode 9 / versionName 0.9.0，最后冷启动模型就绪；麦克风和真实天气关闭。

## 完成的改动

- `PcmMicrophone.java`：移除原来等待静音、收齐整段后才解码的路径。AudioRecord 每次读取 1280 个 PCM16 采样（16kHz 单声道，约 80ms），直接在专属音频线程调用流式 Vosk；Qwen 不参与该线程调度。设备音频缓冲约 2 秒，用于吸收短暂解码抖动，音频不保存到文件。
- `VoskAsr.java`：新增独立流式识别器工厂。使用原生 `acceptWaveForm`、`getPartialResult`、`getResult`、`getFinalResult`；多个识别器只共享只读模型，各自由源线程操作。模型关闭请求会等待活动流关闭，避免麦克风线程仍在解码时释放模型。
- `StreamingTranscriber.java`：管理临时文字变化、句末最终结果、累计解码时间、播报重叠标记、长段保护。音频能量仅辅助记录说话时间，不作为丢弃低音量文字的门槛；临时内容可能修订，不能当成稳定文字。
- `MainActivity.java`：分别显示“实时转写（临时）”“最近完整句”和正式转写记录。临时结果只更新界面，最终结果才记录并异步入 Qwen 队列。临时文字、句末文字在 Qwen 忙碌期间仍继续输出；显示临时更新计数及 Qwen 忙时更新计数。开始/停止按钮放在实时文字附近。
- `DialogueEngine.java`：增加确认接收时间窗口校验。麦克风开始说话时绑定会话和对话阶段，句末保留末尾有声音频帧的接收时间；等待 Vosk 端点或 Qwen 不把及时回答算成迟答。旧阶段语句、播报重叠语句或过期回答不触发操作。
- `app/build.gradle`：升级至 0.9.0；README 和测试同步更新。没有增加模型或原生依赖版本。

没有恢复输入正则、关键词筛选、拼音候选或城市别名替换。Vosk 原文保留；Qwen 输入仍仅移除 ASCII 词间空格。

## 当前流程

```text
麦克风 80ms PCM → 音频线程持续 Vosk 解码
                     ├─ 临时结果 → 实时显示，可修订，不入 Qwen、不写正式日志
                     └─ 句末结果 → 正式显示与独立 IO 记录 → Qwen 专用队列 → 有效阶段内询问/确认
```

Qwen 继续使用独立线程、最多 8 条文本队列、确认优先和旧任务过期机制。实时录音不排在 Qwen 后面；批量诊断样本另有执行器，不占 Qwen 的队列。

Vosk 句末来自声学端点，不保证是语法句号。模型静音尾部阈值约 0.5～2 秒，不能把 80ms 输入帧当作首次出字延迟保证。连续语段达到 20 秒会冲刷当前段最终结果，再开始下一段，可能在语法句子中间分段。停止/重置会取消旧上下文，能冲刷出的未完成尾部只记录，不执行助手行为。

原生接口行为参见 [Vosk 官方 Recognizer 实现](https://github.com/alphacep/vosk-api/blob/master/android/lib/src/main/java/org/vosk/Recognizer.java)；实际运行使用项目固定的 Vosk Android 0.3.75，而非在线 master 代码。

## 关键真机证据

### 临时文字确实先出现

对约 2090ms 的固定郑州 PCM，直接逐帧输入原生 Vosk，并补充静音，由原生端点完成句子：

| 已输入音频位置 | 临时结果 |
|---|---|
| 640ms | 郑州 |
| 1120ms | 郑州 明天 的 |
| 1600ms | 郑州 明天 的 天气 |
| 1840ms | 郑州 明天 的 天气 怎么样 |

这里是合成样本的输入音频位置，不是对真人首次出字墙钟延迟的保证。输入相同语音两次，两条最终结果均为“郑州 明天 的 天气 怎么样”；两次原生句末均正常输出，文件结束冲刷未重复记录。

报告 `events[].audio_ms` 在 partial 事件中表示当前音频帧位置，在 final 事件中表示末尾有声音频帧位置，用于确认接收时间，不是最终回调被触发的时间。

### 临时文字不会进入 Qwen

界面测试在首个非空临时结果后暂停测试音频继续输入，检查实际 TextView：显示“实时转写（流式注入，临时）：郑州”，正式记录为 0，语义队列为 0，未启动语义任务。截图见 `stream-partial-0.9.0.png`。

恢复音频后，只有最终结果才进入正式记录和语义处理。即使 Qwen 执行器被人为阻塞，第二句的 4 次临时更新与最终结果仍完成；Qwen 完成之前已保留 2 条正式句子。重置后旧任务没有触发天气操作。

### 两条链路、确认和天气回归

- 真实 Qwen 推理时，另一条真实 Vosk 流继续产生最终文字；AudioRecord 实际启动、停止，Qwen busy 不阻止采样。
- 注入播报标记时继续识别并记录，但不触发助手。该测试验证标记逻辑，不代表完成真实扬声器声学回声测试。
- Qwen 阻塞时后续音频仍完成，24 条正式记录全部保留，语义积压限制为 8 条，旧语义可跳过而转写不删除。
- 询问之前提前说出的“是的”没有被当作新一轮同意；窗口内提交的确认等待 Qwen 超过 8 秒后仍按接收时间处理。
- 郑州、上海回读，明确拒绝，明确同意后的模拟天气，TTS 完成回调，不支持日期拒绝执行和重置回归通过。

## 内存与性能边界

最终冷启动界面：Vosk 加载 749ms，其时进程 PSS 271 MiB；Qwen 加载 871ms，其时进程 PSS 646 MiB。两者并行加载，各次 PSS 都是整个进程的快照，不能当作单个模型占用，也不能相加为总加载时间。

随后 dumpsys：PSS 约 623 MiB，RSS 约 746 MiB，均为麦克风关闭时的快照，不是流式录音或并发推理峰值。各阶段解码耗时、Qwen 等待/推理耗时和进程 PSS 继续保留在界面与记录中。

线程独立不等于 CPU、内存物理隔离。低算力设备上，Vosk 若持续慢于输入，音频设备缓冲仍可能溢出；本轮没有做长时间压力或树莓派 3B 的 1GB 内存验证。

## 尚未验证

没有真人口音、低音量实录、环境噪声、电机声、真实扬声器回声或长时间连续讲话回归。本轮语音内容证据来自固定合成 PCM；实际麦克风仅验证启动、持续采样条件和停止，不能等同真人识别准确率。天气全部使用模拟数据，未发出真实天气请求；TTS 是回调验证，没有人工听音评审。

“正中/郑重”自动恢复为郑州的既有能力限制没有声称解决。

旧批量 `transcribe` 接口只保留给显式独占样本自检与历史测试；正常麦克风和单个样本按钮均走新增流式路径。显式自检只能在麦克风关闭、普通队列空闲时运行。
