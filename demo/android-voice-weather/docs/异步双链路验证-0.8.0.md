# Vosk 与 Qwen 异步双链路验证（0.8.0）

日期：2026-10-22。设备：Xiaomi/POCO 23049RAD8C，Android 15，arm64。已安装 versionCode 8 / versionName 0.8.0，最后冷启动两模型就绪，麦克风关闭、真实天气关闭。

## 改动

- `MainActivity.java`：Vosk 与 Qwen 分别加载、分别执行；ASR 完成即显示原文、追加独立连续转写区，并提交独立 IO 线程记录。Qwen 处理、排队、失败都不再阻止接收下一段语音。语义结果显示其对应输入，避免与最新转写混淆。
- `PcmMicrophone.java`：采样条件移除 Qwen busy 与播报条件，持续录音分段。与助手播报重叠的整段音频继续转写，但标为只记录，避免回声被当作同意；真人在此期间插话也只记录。
- `IntentBacklog.java`：语义总队列容量 8，确认优先、同类先进先出；满时优先跳过最早普通语义任务，不删除转写记录。普通任务收到后超过 15 秒、确认任务超过 30 秒跳过语义。
- `MainActivity.java`：每条任务固定录音会话、对话阶段、收到时间、默认城市和天气模式。重置、询问、进入确认或结束本轮都会使旧任务失效；窗口内收到的确认可以等待 ASR/Qwen 处理，不能把窗口前的“是的”当作新询问的同意。
- ASR 使用单独线程与最多 4 段等待音频；文字日志、天气网络各用独立执行器。重置会取消排队的 ASR Future，避免显式样本自检等待已经被移除的任务。
- `app/src/main/cpp/qwen_jni.cpp`：Qwen 计算线程从 4 调为 2，Java 工作线程优先级略低于默认值，给转写保留 CPU 余量。
- `app/build.gradle` 升级版本；README 更新运行方式与限制；新增队列单元测试、异步场景设备测试。

没有新增输入正则、关键词筛选、拼音候选或城市别名替换。Vosk 原文保留；Qwen 输入仍仅去掉 ASCII 词间空格作格式归一。有效对话阶段内的完整句子交给 Qwen 判断内容，不先用关键词判断是否天气。

## 两条链路的行为

```text
录音分段 → Vosk 专用线程 → 原文立即显示 → 独立 IO 记录
                              ↓ 非阻塞入队
                       Qwen 专用线程 → 当前对话阶段有效时执行确认流程
```

Qwen 队列满、任务过期、阶段过时或模型失败时，转写仍然保留。设备算力不足导致 ASR 自身的音频队列满时，会明确提示该段未入队；不声称有限设备上绝不丢段。两边共享 CPU、内存和系统调度，线程分离不等于物理性能完全不受影响。

## 验证结果

- 单元测试：16 项通过（原状态机 11 项，语义队列 5 项）。队列覆盖确认优先、先进先出、满队列处理、不能挤掉已有确认、阶段清空。
- 构建：Debug APK 与 AndroidTest APK 成功；Lint 0 error、33 warning。
- 真机设备测试：4 项通过，104.286 秒；分别为 3 项异步场景测试、原确认与天气 UI 回归。连续转写区上移后，再次执行阻塞场景，1 项通过，13.553 秒。没有重新宣称执行所有历史模型准确率测试。
- 冷启动：Vosk 加载约 894ms，其时进程 PSS 273 MiB；Qwen 加载约 965ms，其时整个进程 PSS 647 MiB。两边并行加载，这些数值不能相加为总加载时间，也不能当作独立模型占用。随后 dumpsys PSS 约 640 MiB、RSS 约 762 MiB；均为快照，非峰值。
- 最终布局和截图已检查：上方显示独立转写区，ASR 待处理数量、Qwen 状态与排队数量、文字记录数量与语义跳过数量；当前真实天气请求为 0。

## 异步专项证据

1. **人为阻塞 Qwen 执行器**：提交一条普通文本后，连续送入上海、肯定、否定三个实际 PCM，由真实 Vosk 解码。Qwen 仍阻塞时，4 条文字已经显示，3 条音频转写已经完成，日志文件也已经包含原文。具体时长见 `async-blocked-report-0.8.0.json`，它验证调度独立，不代表持续压力下的性能保证。
2. **语义积压**：继续提交 20 条文字后，共 24 条记录全部保留；语义队列保持 8 条，15 条旧语义任务被跳过。重置后释放旧 Qwen 任务，没有触发旧天气查询。
3. **真实 Qwen 与 Vosk 重叠**：运行实际 Qwen 推理时，真实 Vosk 又完成了一条上海音频；麦克风 AudioRecord 已实际启动。采样条件在 Qwen 忙和播报标记期间都为 true。播报标记通过测试注入，上海转写保留而不触发助手；未将此测试描述为真实扬声器声学回声测试。
4. **确认所属阶段**：在天气询问尚未完成时提前提交“是的”，该任务被阶段切换清除，没有自动查询。随后在确认窗口内提交“是的”，人为延迟 Qwen 超过 8 秒，仍按接收时间处理同意并展示模拟天气。
5. **原 UI 回归**：普通陈述不插话、不支持日期拒绝执行、郑州和上海回读、明确拒绝、同意后模拟天气、TTS 完成回调与重置流程均通过。

初轮测试曾因 Vosk 将“不用”输出为连写形式，而测试固定要求“不 用”导致失败；已修正测试的空格假设，未通过替换识别内容修复。初轮结果保存在忽略的 `build/qa`，最终通过证据见下方。

## 记录与边界

- 连续转写面板显示当前页面会话的最近约 12000 字；完整识别结果在 Qwen 之前交给 IO 线程写入私有 `files/transcripts.jsonl`，与上一份日志合计约 2MB 轮换。重启后日志仍保留，但此版本没有新增历史记录浏览页。
- 仍为约 0.7 秒静音后提交完整分段，最长 10 秒；本轮未改成边说边显示每个字的流式识别。
- 显式样本自检是独占诊断操作，只允许在麦克风关闭、普通队列空闲时运行，不是日常转写链路。
- 没有真人口音/噪声/扬声器回声的准确率回归，没有长时间负载或树莓派 3B 实测；本轮天气全部模拟，未发出真实天气请求。没有宣称解决 0.7.0 已记录的“正中/郑重→郑州”恢复问题。
