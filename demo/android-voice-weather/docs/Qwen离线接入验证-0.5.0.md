# Qwen 离线接入与真机对比（0.5.0）

## 实现范围

- 在现有独立 Android Java Demo 中加入 llama.cpp JNI，不启本地 HTTP 服务、不上传音频或转写。
- Qwen3-0.6B 使用官方 Q8_0 GGUF，经固定版本量化工具在本机重量化为 Q4_K_M；约 378 MiB，单独部署到应用外部私有目录。模型与源码固定信息见 `qwen-model-manifest-0.5.0.json`。
- 当前 APK 仅 arm64-v8a；Android 最低 API 26。API 29+ 使用系统 ICU 生成近音短名单，旧版本不扩展 ICU 候选。NDK 28.2.13676358 / CMake 3.22.1。
- 开关默认关闭；关闭时保持原规则路径，打开时逐句并列显示规则与组合路径的候选和耗时。规则可明确解析的城市、普通聊天及不受支持的句子跳过模型。
- 额外提供 A/B 自检按钮，只比较固定文字转写，不播报、不调用天气。结果保存在应用 `files/qwen-city-ab.json`。
- CPU 4 线程、1024 token 上下文、48 token 输出上限、非思考模式、15 秒原生截止与取消。主线程不做模型加载或推理。
- 词库 / Vosk 近音候选 → Qwen 在短名单或 null 中选择 → JSON 语法约束 → 城市、日期、状态机复核 → 回读并等待明确同意。LLM 不创建天气意图、不改日期、不直接执行天气请求。
- 加载前验证固定文件长度及 SHA-256。`tools/deploy_qwen.py` 使用临时文件、手机校验及原子改名，避免半传输文件进入原生层。

## 选型试验记录

保留了两轮开发报告，未将它们计为最终回归通过：

1. `qwen-device-initial-0.5.0.json`：直接要求小模型纠错、仅允许完整城市表，四个同音文本都返回 null。
2. `qwen-device-prompt2-0.5.0.json`：加入提示词示例后，出现重复输出示例城市“杭州”的问题；既有郑州规则能拦截冲突，但未知城市槽可能被错误猜测。因此放弃自由生成城市的做法。
3. 最终版增加独立近音证据与短名单语法约束；不能输出与候选无关的城市。正确候选由规则、词库和 LLM 共同产生，不能将收益归因于 LLM 单独纠错，更不能当作声学识别能力提升。

第一次模型传输完成前提前启动了测试，已中止且不计入有效结果；手机端完整 SHA-256 一致后重新运行。此后补充了文件长度和 SHA 校验，以及原子部署脚本。

UI 首轮测试错误地从历史日志判断第二次加载已完成，在模型尚未就绪时点了 A/B，因而等待超时。已改为等待当前 `llmReady` 状态后重跑。

## 真机环境与证据

设备为当前连接的 Xiaomi / POCO `23049RAD8C`，Android 15，arm64-v8a；安装版本 code 5 / name 0.5.0。保留原 Demo 数据，无卸载。

完整真机回归 **OK (4 tests)，107.489 秒**，见 `instrumentation-0.5.0.txt`。既有音频 A/B、真实 Open-Meteo 查询和 TTS 完成回调、Qwen 实际推理及取消恢复、开关/回读/拒绝/重置/A/B 自检均通过。没有进行真人麦克风或人工听音验证。

`qwen-device-report-0.5.0.json` 记录最终完整回归的以下实测：

| 固定语音转写文本 | 规则结果 | 组合结果 | 模型阶段耗时 |
| --- | --- | --- | --- |
| 正中明天天气怎么样 | 郑州 | 郑州，需确认 | 1978 ms |
| 郑重明天天气怎么样 | 郑州 | 郑州，需确认 | 1905 ms |
| 正州明天天气怎么样 | 无法解析 | 郑州，需确认 | 1918 ms |
| 商海明天天气怎么样 | 无法解析 | 上海，需确认 | 1893 ms |
| 上海明天天气怎么样 | 上海 | 上海，跳过模型 | 0 ms |

这 5 条开发正例中，规则识别目标 3/5，组合路径 5/5；不是独立盲测数据，也不是所有城市的正确率。四条实际模型调用的短名单均只有一个城市，尚不能证明 LLM 在多候选消歧中的额外价值。

5 条控制文本（郑重提醒、正中间、后天、否定、丢失天气词）都没有新增纠错。原规则会将“郑重提醒…”视作可能天气意图，随后城市解析失败；最终没有回读、没有查询，不将此写成规则已识别为普通聊天。

模型加载及校验约 682 ms（不含初次构建候选词表）；加载模型后进程 PSS 588945 KB，Vosk 与 Qwen 共存测试时 728774 KB。这是特定测试时刻整个进程的 PSS，不能解释为模型净占用或内存峰值。

合成音频共 6 条，每条只运行一次 Vosk 5 候选，向两条文字解析路径提供相同候选。郑州普通/快速、上海共 3 条正例均保持正确；另一音色快速郑州压力样本把“天气”听成“坚强”，两条路径均未恢复意图；2 条普通陈述控制无新增纠错。音频正例 3/4 成功，当前样本没有显示接入 LLM 后的语音正确率提升。

UI 一键 A/B 的 8 条结果见 `qwen-ui-ab-0.5.0.json`；该次 UI 操作中的四次模型调用比独立推理测试慢，具体耗时保留在报告中，不将约 1.9 秒写成稳定上限。UI 测试的屏幕文字快照见 `qwen-ui-flow-0.5.0.txt`。

## 运行方式

```bash
python3 tools/prepare_qwen.py
./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest lintDebug
android run --device=<serial> --apks=app/build/outputs/apk/debug/app-debug.apk --activity=cn.aihongbo.voiceweather.MainActivity
python3 tools/deploy_qwen.py --device <serial> --adb <adb-path>
adb -s <serial> install -r -t app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s <serial> shell am instrument -w -e live true cn.aihongbo.voiceweather.test/androidx.test.runner.AndroidJUnitRunner
```

`QwenCityTest` 实际加载手机模型，输出固定转写与合成 PCM 的对比、模型加载/PSS及取消后恢复结果。`QwenUiFlowTest` 注入 ASR 候选，检查开关、回读、拒绝、重置取消、再次加载和 A/B 按钮；它不属于真人语音测试。其余两项沿用已有音频与天气流程回归。

## 尚未验证与限制

- 尚未用用户现场语音、口音、远场、多说话人或电机噪声做配对测试；普通聊天误触率、长期监听、温升及续航没有统计。
- 没有独立测量 LLM 相对“仅近音短名单”的收益；小模型的开放式纠错不可靠，默认仍保留关闭开关的规则基线。
- 实际推理运行于本机 CPU，但本轮未切断整机网络进行断网回归；天气接口始终需要网络，天气内容不由 LLM 编造。
- 测试了原生取消和下一次调用恢复，尚未专门注入 15 秒自然超时、进程被杀或真实低内存条件。
- 没有树莓派 3B 实测；手机约 0.6 GiB 以上的组合进程 PSS 与秒级耗时不能直接外推到树莓派 1GB 内存环境。
