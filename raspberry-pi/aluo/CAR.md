# 阿洛智能小车

当前：软件实现及模拟验证阶段，真实接线未确认。GPIO输出默认禁用；未标定前不要设置armed=true。

## 指令与编排

支持先“你好阿洛”再说动作，也支持直接说“阿洛前进一下”等完整指令。运动/舵机动作均先回读参数，等待8秒内明确确认。取消、超时不执行。“停车”“阿洛停止”“急停”“停止跳舞”在任意状态直接请求停止，无需口头确认。不能把“不要前进”或包含动作词的任意句子识别为运动。

| 指令 | 默认计划 |
|---|---|
| 前进一下 | PWM25%，0.5秒 |
| 后退一下 | PWM20%，0.3秒；默认禁用 |
| 左转/右转一下 | 前轮相对中位±10度，PWM20%，0.5秒；实际左右符号需标定 |
| 跳舞/跳摇摆舞 | 前轮±10度与超声波云台±15度摇摆，不驱动车轮 |
| 跳招手舞 | 另一种前轮/云台交替组合，不驱动车轮 |
| 跳小碎步舞 | 转向与两次PWM20%、0.2秒前进组合 |

这些是时间/PWM控制，不代表厘米、角速度或精确位移。当前按一个L298N A通道驱动后轮、前舵机转向建模；若实际使用B通道或双独立电机，需先补充拓扑后适配，不能凭示例接线推断。

## 配置与启用

复制car.example.json为car.json，所有pins采用BCM编号。示例的针脚为null，舵机中位、角度及脉宽仅为待标定占位值。确认以下信息后才能填写并启用：

- IN1/IN2/ENA、前轮舵机、超声波云台舵机、Trig/Echo实际针脚；全部唯一，无其他服务占用。
- ENA跳线帽已拆，ENA接PWM，IN1/IN2控制方向；停车时先拉低ENA，再拉低方向脚。
- Echo为3.3V安全电平；HC-SR04的5V Echo需分压或电平转换。超声波型号需核对。
- 舵机使用适当的独立电源并与Pi/L298N共地，机械限位、中位、脉宽、左右方向已实测标定。
- 在车轮架空、有物理断电开关的条件下，先展示单个动作的目标、PWM、角度和时长，用户确认后再真实测试。

GPIO后端使用gpiozero的PWMOutputDevice/AngularServo及DigitalInputDevice，硬件依赖尚未安装/验证。不要沿用旧demo中的示例针脚或假定wiringPi编号等于BCM。

开启car.json的armed及各项已核实标记后重启aluo.service才会初始化硬件。开机不会自动跳舞或前进。舵机初始化initial_angle=None，不主动归中；动作结束断开舵机脉冲，不承诺断电后机械自动归中。

## 模拟测试

```sh
# 不导入gpiozero，不打开GPIO；距离为明确的合成值，不是真实测距
.venv/bin/python aluo.py --text --simulate-car
# 输入：阿洛跳舞 → 是的；或：阿洛前进一下 → 是的
python3 -m unittest discover -s tests
```

服务默认不带simulate-car，配置未启用时会明确回复硬件未启用；不会把模拟执行说成真实运动。

## 安全边界与未验证项

- 前进时云台朝前，等待250ms稳定后测距；每约50ms重新测距，测量超时即停止。35cm阈值仅为软件保守初值，不是已验证的刹车距离。
- 无后方传感器，后退只能在额外启用reverse_enabled并逐次确认后方无人无障碍时执行，不具备后方避障能力。
- 总计划不超过6秒；每段不超过0.6秒、PWM不超过25%；取消、动作异常、正常结束和正常服务退出均停止输出。
- 语音识别与播报存在延迟；语音“急停”不能替代物理急停。播报期间不采集，SIGKILL/断电/驱动故障无法由Python保证停止，需物理断电开关及ENA外部下拉等硬件措施。
- gpiozero舵机软件PWM的抖动、供电与真实转向、测距精度、停止距离尚未验证；标定不通过不能启用行驶。
- 不提供无人值守自主导航，不因前方障碍自动倒车。需要后续真人场地验收。

GPIO接口依据：https://gpiozero.readthedocs.io/en/latest/api_output.html 。

### 照片及后续确认

用户确认ENA跳线帽已拆下。提供的照片显示双探头测距模块，外观接近HC-SR04系列，但正面支架遮挡型号/丝印，不能据此区分HC-SR04、3.3V兼容变种或其他模块。Trig/Echo接线已确认，额定供电与Echo电平仍未核实。需要背面型号及VCC/Trig/Echo/GND丝印照片；不要求带电拆卸。

用户选择MG996R暂留3.3V并稍后改装。已保留实际接线记录，软件不启用该舵机，不进行依赖转向的行驶测试。ENA确认并不代表其他硬件条件已通过，armed保持false，本轮没有远程GPIO操作。

### 驱动板近照核对

三张近照确认丝印为YFROBOT ©2016，不是DFRobot。输出标M1/M2；以散热片在上、控制排针在下观察，排针上排从左到右ENA/VCC/ENB/VCC，下排IN1/IN2/IN3/IN4。照片显示控制插头覆盖部分丝印，靠ENB/IN3区域有接线，但不能从遮挡照片确认每根线与Pi针脚的完整对应。需断电逐根核对：当前软件测试对象为BCM5→IN1、BCM6→IN2、BCM19→ENA，对应M1。不能混用ENB/IN3/IN4的M2控制。未追加电机脉冲，接线/供电原因尚未最终确认。
